# รัน edge บนรีโมต SIYI UniRC 7 Pro (แบบ A, สำหรับทดสอบ)

ย้าย gateway จากโน้ตบุ๊กไปรันบนรีโมตเอง (รีโมตเป็น Android ใช้ Termux) รีโมตต่อออกไปหา server เอง และ**ส่งภาพกล้องเข้า media server บน .13** เหมือน DJI Dock ไม่ต้องมีโน้ตบุ๊กคั่น และไม่ต้องรู้ IP ของรีโมต

```
FC → air unit → วิทยุ SIYI → UniRC 7 Pro [Termux: gateway + ffmpeg] ──Wi-Fi ออฟฟิศ──► 192.168.20.13:8090  (ข้อมูลรถ)
กล้อง (.25) ──────────────────────────────────┘                     └──RTSP──────► 192.168.20.13:18554 (ภาพ)
เบราว์เซอร์ ◄──WebRTC── 192.168.20.13:18889
```

> **แบบเดิม (pull):** MediaMTX รันบนรีโมตและเบราว์เซอร์ดึงภาพจากรีโมตตรงๆ ยังใช้ได้ถ้าใน `site.json` ใช้ `stream.whep` แทน `stream.push` (ต้องทำข้อ 2 ส่วน REMOTE_IP และข้อ 5) ใช้เมื่อ .13 ยังไม่ได้เปิด media server

> **ทำหลังจากต่อผ่านโน้ตบุ๊กได้แล้ว** ([`deploy/edge/FIRST_CONNECTION_TH.md`](../edge/FIRST_CONNECTION_TH.md)) จะได้รู้ว่าถ้าไม่ผ่าน ปัญหาอยู่ที่การย้ายมารีโมต ไม่ใช่ที่รถ
> ถ้ามาทางรีโมตเลยโดยไม่มีโน้ตบุ๊ก ให้ใช้ `probe.sh` (ข้อ 3.5) แยกปัญหาฝั่งรถออกก่อนเปิด gateway
> **ยังไม่เคยทดสอบบนรีโมตจริง** ข้อที่มี 🧪 คือสิ่งที่ยังไม่รู้ว่าจะผ่าน ถ้าไม่ผ่านให้กลับไปใช้โน้ตบุ๊ก (ข้อ 10)

กฎเดิมทุกข้อยังใช้: รถอยู่ `SHADOW` (ดูอย่างเดียว) และ **gateway ได้ทีละตัว** ห้ามเปิดของโน้ตบุ๊กกับของรีโมตพร้อมกัน

## 0. เตรียมชุดบนโน้ตบุ๊ก

```powershell
npm run kit:remote
```

ได้โฟลเดอร์ `deploy\remote\dist\edge-kit\` (gateway ไฟล์เดียว, สคริปต์, config, คู่มือนี้)
ก๊อปทั้งโฟลเดอร์ไปที่ **Download** ของรีโมต เช่น เสียบสาย USB แล้วลากไฟล์ (MTP) หรือส่งผ่าน Google Drive

## 1. ติดตั้ง Termux บนรีโมต 🧪

- โหลด Termux จาก **F-Droid** หรือ **GitHub releases** (`termux-app_..._arm64-v8a.apk`) **ไม่ใช้ตัวใน Play Store** เพราะเก่าและติดตั้งแพ็กเกจไม่ได้
- อนุญาตให้ติดตั้งแอปจากแหล่งนี้เมื่อรีโมตถาม
- Settings → Apps → Termux → Battery → **Unrestricted** ไม่อย่างนั้น Android อาจปิด Termux ตอนพักจอ

## 2. ต่อ Wi-Fi ออฟฟิศบนรีโมต 🧪

- ต่อ Wi-Fi ที่ไปถึง `192.168.20.13` ได้ วิทยุ SIYI ใช้งานต่อได้ตามปกติ
- แบบส่งภาพเข้า .13 (ค่าเริ่มต้น) **ไม่ต้องจด IP ของรีโมต**
- แบบเดิม (pull) เท่านั้น: จด **IP ของรีโมตฝั่ง Wi-Fi** (Settings → Wi-Fi → แตะชื่อเครือข่าย → IP address ต่อไปเรียกว่า `REMOTE_IP`) และควรจองไว้ที่ router

## 3. ติดตั้งใน Termux

ต้องมีเน็ต: จะดาวน์โหลด Node.js, ffmpeg (ส่งภาพ) และ MediaMTX v1.9.3 (สำหรับแบบเดิม 18.5 MB จาก GitHub ทางการ ตรวจขนาดไฟล์ก่อนติดตั้ง)

```bash
termux-setup-storage                      # อนุญาตให้ Termux อ่าน Download
cp -r ~/storage/downloads/edge-kit ~/edge-kit
bash ~/edge-kit/install.sh
```

ไฟล์จะอยู่ใน `~/edge` (ไฟล์ที่อยู่ใน Download รันตรงๆ ไม่ได้ ต้องก๊อปเข้า Termux ก่อน)

## 3.1 ปุ่มบนหน้าจอโฮม (ไม่ต้องพิมพ์คำสั่ง)

`install.sh` สร้างปุ่มไว้ 4 ปุ่ม: **1 เริ่ม Edge**, **2 หยุด Edge**, **3 สถานะ Edge**, **4 ตรวจลิงก์รถ**

1. ติดตั้งแอป **Termux:Widget** จาก**แหล่งเดียวกับ Termux** (F-Droid คู่ F-Droid หรือ GitHub คู่ GitHub ถ้าคนละแหล่งจะติดตั้งไม่ได้หรือกดแล้วไม่ทำงาน)
2. กดค้างที่หน้าจอโฮม → **Widgets** → **Termux:Widget** → ลากมาวาง
3. แตะปุ่มในวิดเจ็ต: จะเปิดหน้าต่าง Termux รันงานนั้น แล้วรอให้กด Enter ก่อนปิด
4. ถ้ากดแล้วไม่มีอะไรเกิดขึ้น: Settings → Apps → Termux → **Display over other apps** → อนุญาต

ทุกปุ่มเรียกสคริปต์เดียวกับที่พิมพ์เอง (`start.sh`, `stop.sh`, `status.sh`, `probe.sh`) รัน `install.sh` ใหม่เมื่อไหร่ ปุ่มจะถูกสร้างใหม่ตามชุดล่าสุด

## 3.5 ตรวจลิงก์กับรถ (อ่านอย่างเดียว)

เปิดรถ (กล้องห้อยหัวลง) ใน UniGCS ตั้ง Datalink 1 = UDP และ baud ให้ตรงกับพอร์ตของบอร์ดที่ต่อกับ air unit แล้วปิด UniGCS (Settings → Apps → UniGCS → Force stop) จากนั้น:

> หลังเปลี่ยน Datalink 1 เป็น UDP แล้ว ถ้าจะใช้ UniGCS เองต้องตั้งการเชื่อมต่อใน UniGCS เป็น **UDPCL** ที่ `192.168.144.20` พอร์ต `19856` ด้วย ไม่อย่างนั้น UniGCS เห็นรถแต่ค้างที่ "parameter loading" (เจอ 27 ต.ค.)

```bash
~/edge/probe.sh
```

- ต้องได้ **Autopilot heartbeat PASS** และ **Disarmed PASS** ก่อนไปขั้นต่อไป
- รายงานอยู่ใน `~/edge/reports/` (มี firmware ที่บอร์ดแสดง)
- ถ้าขึ้น "No data at all" ให้ลอง `~/edge/probe.sh --host 127.0.0.1` ถ้าผ่าน ให้แก้ `link.host` ใน `site.json` เป็น `127.0.0.1` ด้วย
- probe ไม่เทียบไฟล์ param (ไฟล์ในโปรเจกต์ทำไว้สำหรับ UniFC 6 Pico) ถ้าจะเทียบ ใช้ `--params <ไฟล์>`

## 4. แก้ config บนรีโมต

รถ Matek H743-WING (ชุดทดสอบ 27 ต.ค.) ให้เริ่มจากไฟล์ตัวอย่างของคันนี้ก่อน:

```bash
cp ~/edge/site.matek-ugv.example.json ~/edge/site.json
```

แล้วแก้ใน `site.json` แค่ 2 ค่า:

| แก้ | ค่า |
|---|---|
| `key` | gateway key จาก server (ถ้าพิมพ์ยาก ใช้วิธี `read -rep "key: " K` แล้วสั่ง node ตามที่ใช้วันที่ 27 ต.ค.) |
| `geo` | จุดอ้างอิงแผนที่ที่ตั้งจาก GPS (ยังไม่มีก็ใช้ค่าในไฟล์ไปก่อน) |

ภาพกล้องตั้งไว้แล้วเป็น `"stream": { "rtsp": "rtsp://192.168.144.25:8554/main.264", "push": true }` คือให้ gateway ส่งภาพเข้า .13 server จะบอก gateway เองว่าส่งไปที่ไหน และบอกเบราว์เซอร์ว่าดูภาพที่ไหน **ไม่ต้องใส่ IP รีโมต และไม่ต้องทำข้อ 5**

ถ้ากล้องอยู่ที่ IP หรือ path อื่น ให้แก้ `stream.rtsp` ให้ตรง กล้องต้องส่งเป็น **H.264** ถ้ากล้อง SIYI กลับไปส่ง H.265 เอง gateway จะสั่งให้ main stream กลับเป็น H.264 และรีสตาร์ตกล้องให้โดยอัตโนมัติ (ไม่เกิน 1 ครั้งต่อ 10 นาที ภาพหายไปราว 10–20 วินาที) ถ้าไม่ต้องการให้ทำเอง ใส่ `"fixCameraCodec": false` ที่อุปกรณ์นั้น

**แบบเดิม (pull) เท่านั้น:** ใช้ `"whep": "http://REMOTE_IP:8889/ugv-01/whep"` แทน `"push": true` แก้ `webrtcAdditionalHosts: [REMOTE_IP]` ใน `nano ~/edge/mediamtx.android.yml` แล้วทำข้อ 5

## 5. อนุญาตแหล่งวิดีโอของรีโมต (แบบเดิม pull เท่านั้น ครั้งเดียวต่อ IP)

หน้าเว็บ (admin) → **แหล่งวิดีโอที่อนุญาต** → ใส่ `http://REMOTE_IP:8889` → `อนุญาต`
(หรือจากโน้ตบุ๊ก: `deploy\edge\Set-EdgeOrigin.ps1 -Origin http://REMOTE_IP:8889`)

รายการนี้เก็บได้หลายที่อยู่ ของโน้ตบุ๊กยังอยู่ สลับกลับไปใช้โน้ตบุ๊กได้โดยไม่ต้องตั้งใหม่

## 6. ปิดของโน้ตบุ๊ก

- กด Ctrl+C ในหน้าต่าง `Start-Edge.ps1` และปิดหน้าต่าง MediaMTX
- บนรีโมต: **ปิด UniGCS** (Force stop) ระหว่างที่ gateway ทำงาน ทดสอบ 27 ต.ค. พบว่าเมื่อทั้งสองต่อประตู `19856` พร้อมกัน:
  - UniGCS ยังเห็นข้อมูลรถ แต่**คำสั่งจาก UniGCS (เช่นเปลี่ยนโหมด) ไปไม่ถึงบอร์ด** และไม่มีอะไรเตือน
  - ตอน UniGCS ต่อหรือโหลด parameter ใหม่ platform ขาดข้อมูลรถไปประมาณ 2 นาที
  - คนขับยังใช้คันโยกและสวิตช์บนรีโมตได้ตามปกติ (ไม่ผ่าน datalink)
  - ถ้าต้องใช้ UniGCS: หยุด gateway ก่อน (Ctrl+C) ใช้เสร็จแล้วปิด UniGCS แล้วค่อยรัน `start.sh` ใหม่

## 7. เปิดบนรีโมต

```bash
~/edge/start.sh
```

- ต้องเห็น `platform server ... : OK`, `MediaMTX: running`, `connected to ws://192.168.20.13:8090` และ `registered 1 device(s)`
- เปิด Termux ค้างไว้ สคริปต์ล็อกไม่ให้เครื่องหลับ (`termux-wake-lock`) กด Ctrl+C เพื่อหยุดทั้งคู่
- ดูสถานะจากอีกหน้าต่าง Termux (ปัดจากซ้าย → New session): `~/edge/status.sh`

## 8. ตรวจบนหน้าจอ

ตรวจแบบเดียวกับขั้นที่ 10 ของคู่มือโน้ตบุ๊ก แล้วเพิ่มอีก 3 ข้อที่เป็นเรื่องของรีโมตโดยเฉพาะ:

| ตรวจ 🧪 | ผ่านเมื่อ |
|---|---|
| ภาพจากกล้อง | หน้าต่าง gateway ขึ้น `video pushed to rtsp://pub:***@192.168.20.13:18554/ugv-01 (h264)` และเบราว์เซอร์เห็นภาพสด (ดูได้จากทุกเครื่องที่ถึง .13 ไม่ต้องอยู่ Wi-Fi เดียวกับรีโมต) |
| พักจอรีโมต 2 นาที | รถยังไม่ขึ้น STALE บนหน้าจอ (Android ไม่ปิด Termux) |
| รีโมตเปิดทุกอย่างพร้อมกัน 15 นาที | ไม่ร้อนจนเตือน, UniGCS และการบังคับด้วยมือยังลื่น |

## 8.1 ขับรถจากหน้าเว็บ

ต้องตั้ง 3 ที่ ครั้งแรกครั้งเดียว:

**1) รีโมต: เปิดการขับใน `site.json`** (ไฟล์ตัวอย่างชุดใหม่มี `"teleop": true` อยู่แล้ว ถ้าใช้ `site.json` เดิมให้สั่งบรรทัดนี้) แล้วกดปุ่ม "2 หยุด Edge" ตามด้วย "1 เริ่ม Edge"

```bash
node -e "const f=process.env.HOME+'/edge/site.json',fs=require('fs'),c=JSON.parse(fs.readFileSync(f,'utf8'));c.devices.find(d=>d.deviceId==='UGV-01').teleop=true;fs.writeFileSync(f,JSON.stringify(c,null,2))"
```

ค่าเริ่มต้น: คันเร่งไม่เกิน 30% เลี้ยวไม่เกิน 60% ไม่มีคำสั่งจากเว็บเกิน 0.5 วินาทีรถหยุดเอง ใช้ช่อง 1 เลี้ยว ช่อง 3 คันเร่ง (ตรงกับรถคันนี้) จะปรับก็ใส่เป็น `"teleop": { "maxThrottle": 0.2 }`

**2) รถ (Mission Planner ผ่าน USB)**

| พารามิเตอร์ | ค่า | ทำไม |
|---|---|---|
| `RC_OVERRIDE_TIME` | `1` | ถ้า gateway หลุดกลางทาง รถคืนคันบังคับให้รีโมตภายใน 1 วินาที |
| `SYSID_MYGCS` | `255` (ค่าเดิม) | รถรับคำสั่งขับจาก gateway |
| สวิตช์โหมด `MODE_CH` | ช่อง 10 หรือ 11 (`MODE1`=4 HOLD) | คนถือรีโมตสลับเป็น HOLD ได้ทันที **ควรตั้งก่อนขับจริง** |
| `FS_GCS_ENABLE` | `1` หลังตั้งสวิตช์โหมดแล้ว | gateway หายไป รถเข้า HOLD (ถ้ายังไม่มีสวิตช์โหมด รถจะค้าง HOLD จนรีสตาร์ต) |

**3) หน้าเว็บ** (ศูนย์ควบคุม → UGV-01 → กล่อง "ขับ")

1. หัวหน้า (supervisor) ใส่เหตุผล กด "อนุญาตให้ขับสด (LIVE MANUAL)" แล้วยืนยันรหัสผ่าน
2. คนถือรีโมต: ตั้งโหมด MANUAL แล้ว arm ด้วยสวิตช์ ch12
3. ผู้ควบคุม (operator) ติ๊กช่องยืนยัน กด "เริ่มขับ" แล้วกด W A S D (หรือลูกศร) ค้างไว้ หรือลากแป้นกลม ปล่อยมือ = รถหยุด กด Space, Esc หรือปุ่มแดงเพื่อจบการขับ
4. เลิกขับแล้ว หัวหน้ากด "กลับเป็น SHADOW"

ระหว่างที่เว็บขับ คันเลี้ยวกับคันเร่งบนรีโมตใช้ไม่ได้ แต่ **สวิตช์ arm (ch12) ใช้ได้ตลอด ใช้เป็นตัวหยุดฉุกเฉิน** ถ้าจะเอาคันบังคับคืน กดหยุดบนเว็บ หรือ disarm

**ครั้งแรกให้ยกล้อลอยก่อน** แล้วตรวจ:

| ตรวจ 🧪 | ผ่านเมื่อ |
|---|---|
| กด W | ล้อหมุนไปข้างหน้า (ถ้ากลับด้านใส่ `"teleop": { "reverseThrottle": true }`) |
| กด D | เลี้ยวขวา (ถ้ากลับด้านใส่ `"reverseSteer": true`) |
| ปล่อยปุ่ม | ล้อหยุดทันที |
| ปิดแท็บเบราว์เซอร์ระหว่างกด W | ล้อหยุดภายในราว 0.5 วินาที แล้วรีโมตกลับมาบังคับได้ |
| disarm ด้วย ch12 ระหว่างขับ | ล้อหยุด กล่อง "ขับ" ขึ้นว่า disarmed |

## 8.2 รั้วเสมือนตอนวิ่งภารกิจ AUTO (`missionFence`)

ถ้าบอร์ดเปิดรั้ว (`FENCE_ENABLE=1`) ค้างไว้ จะ arm ไม่ได้จนกว่าจะมีตำแหน่ง GPS รถเลยใช้ในอาคารไม่ได้ จึงตั้งแบบนี้:

- **บอร์ด**: `FENCE_ENABLE=0` ส่วนรูปร่างรั้วตั้งไว้บนบอร์ดเหมือนเดิม (`FENCE_TYPE=2` วงกลม, `FENCE_RADIUS`, `FENCE_ACTION=2` HOLD)
- **รีโมต**: ใส่ `"missionFence": true` ในอุปกรณ์ของรถใน `site.json` (ไฟล์ตัวอย่างชุดใหม่มีอยู่แล้ว) แล้วเริ่ม Edge ใหม่

gateway จะทำงานแบบนี้:
1. เวลาสั่งวิ่งเส้นทางจากหน้าเว็บ gateway **เปิดรั้วก่อน** แล้วค่อยเปลี่ยนเป็น AUTO ถ้าบอร์ดไม่ยอมเปิดรั้ว ภารกิจจะไม่เริ่ม และหน้าเว็บขึ้นเหตุผลให้
2. พอคนถือรีโมต **disarm** gateway **ปิดรั้วให้เอง** ครั้งต่อไปจึง arm ในอาคารได้โดยไม่ต้องมี GPS
3. ถ้าบอร์ดรีบูต รั้วจะกลับเป็นปิดเสมอ เพราะคำสั่งเปิดรั้วไม่ถูกบันทึกถาวร

| ตรวจ 🧪 | ผ่านเมื่อ |
|---|---|
| arm ในอาคาร ไม่มี GPS | arm ได้ ขับ MANUAL ได้ |
| สั่งวิ่งเส้นทางกลางแจ้ง (มี GPS) | Mission Planner / UniGCS เห็นรั้วเปิดก่อนรถเข้า AUTO |
| disarm หลังจบภารกิจ | รั้วปิด, arm ใหม่ในอาคารได้ |

## 9. อัปเดตชุดในภายหลัง

`npm run kit:remote` บนโน้ตบุ๊ก ก๊อปโฟลเดอร์ใหม่ไปทับใน Download แล้ว:

```bash
~/edge/stop.sh
rm -rf ~/edge-kit && cp -r ~/storage/downloads/edge-kit ~/edge-kit && bash ~/edge-kit/install.sh
```

`install.sh` เก็บ `site.json` เดิมไว้ ไม่เขียนทับ (ถ้า `mediamtx.android.yml` ถูกเขียนทับ ให้ใส่ `REMOTE_IP` ใหม่)

## 10. กลับไปใช้โน้ตบุ๊ก

```bash
~/edge/stop.sh
```

จากนั้นรัน `Start-Edge.ps1` บนโน้ตบุ๊กตามปกติ

## ถ้ามีปัญหา

| อาการ | ลองแก้ |
|---|---|
| `pkg` ติดตั้งไม่ได้ / หาแพ็กเกจไม่เจอ | Termux มาจาก Play Store: ลบแล้วลงจาก F-Droid หรือ GitHub |
| `This kit needs aarch64` | รีโมตไม่ใช่ ARM 64 บิต ใช้แบบนี้ไม่ได้ กลับไปใช้โน้ตบุ๊ก |
| MediaMTX ขึ้น `netlink ... permission denied` | ตรวจว่า `webrtcIPsFromInterfaces: no` และใส่ `REMOTE_IP` ใน `webrtcAdditionalHosts` แล้ว |
| MediaMTX หยุดทันทีด้วย error อื่น | ดู `~/edge/logs/mediamtx.log` แล้วรันแค่ gateway บนรีโมตก่อน (ดูภาพผ่านโน้ตบุ๊กไปพลาง) |
| gateway ไม่ได้ heartbeat จากรถ | datalink ใน UniGCS ต้องเป็น UDP; ปิด datalink ของ UniGCS; 🧪 ลองเปลี่ยน `link.host` ใน `site.json` จาก `192.168.144.20` เป็น `127.0.0.1` |
| รถหลุดเป็น STALE เมื่อพักจอ | Battery → Unrestricted, ไม่ปัด Termux ทิ้ง, ดูว่ามีแจ้งเตือน "wake lock held" ของ Termux |
| `ffmpeg is not installed` / ชิ้นส่วนกล้องขึ้น `ffmpeg not found` | รัน `install.sh` ใหม่ หรือ `apt install -y ffmpeg` |
| gateway ขึ้น `the server gave no video publish address` | .13 ยังไม่ได้เปิด media server (`MEDIA_INGEST_URL` / `MEDIA_PUBLIC_URL` ใน `.env.server` และบริการ `media` ใน compose) ใช้แบบเดิม (pull) ไปก่อน |
| gateway ขึ้น `video push stopped: ... 401 Unauthorized` | key ของ gateway ถูกยกเลิก หรือรถถูก gateway ตัวอื่นรับไป ตรวจว่ามี gateway รันอยู่ตัวเดียว |
| gateway ขึ้น `video push stopped: ... Connection refused` / `timed out` | ถ้าเป็นที่กล้อง (`192.168.144.25`): กล้องยังบูตไม่เสร็จหรือ IP ผิด ถ้าเป็นที่ `192.168.20.13:18554`: บริการ `media` บน .13 ไม่ได้รัน gateway ลองใหม่เองทุก 2–30 วินาที |
| ภาพจอดำ / เว็บขึ้น "เซิร์ฟเวอร์วิดีโอขัดข้อง (400)" | กล้องส่ง H.265 (media server ขึ้น `doesn't contain any supported codec`, ชิ้นส่วนกล้องบนเว็บเขียนว่า "The camera sent H.265"): gateway รุ่นใหม่สลับกลับเป็น H.264 และรีสตาร์ตกล้องให้เอง รอ 20 วินาที ถ้ายังไม่หาย (เฟิร์มแวร์กล้องไม่รับคำสั่งรีสตาร์ต) ให้ปิดเปิดรถ ใช้ gateway รุ่นเก่าอยู่: สั่งผ่าน SDK ของกล้อง (คำสั่ง `0x21`) แล้วปิดเปิดรถ |
| UniGCS ค้าง "parameter loading" | การเชื่อมต่อใน UniGCS ต้องเป็น UDPCL `192.168.144.20:19856` เมื่อ Datalink 1 = UDP และต้องไม่มี gateway รันอยู่ |
| UniGCS กดเปลี่ยนโหมดไม่ไป | gateway รันอยู่ด้วย: หยุด gateway หรือใช้สวิตช์โหมดบนตัวรีโมตแทน |
| แผงอุปกรณ์บนเว็บขึ้น STALE ทั้งที่รถส่งข้อมูล | ดูด้วยบัญชี admin: admin ไม่ได้รับข้อมูลสด ให้ดูด้วยบัญชีหัวหน้าเวรหรือผู้ควบคุม |
| เครื่องอื่นไม่เห็นภาพ | อยู่ Wi-Fi เดียวกับรีโมต, ทำข้อ 5 แล้ว, gateway รีสตาร์ทหลังข้อ 5 |
| `Start-Edge.ps1` บนโน้ตบุ๊กกับรีโมตเปิดพร้อมกัน | ปิดตัวใดตัวหนึ่งทันที (gateway ได้ทีละตัว) |
